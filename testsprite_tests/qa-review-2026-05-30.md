`npm run seed:test-users` aborted partway, leaving accounts with no org → login bounced them

| Table                       | Seed/app referenced                                | Real schema                                                             | Fix                                             |
| --------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------- |
| `organizations` (wipe)      | plain cascade delete                               | cascade hits `player_competition_stats.competition_id` NOT NULL → 23502 | delete pcs first; check every wipe error        |
| `match_events`              | `half`                                             | no such column (`type/minute/player_name`)                              | removed `half`                                  |
| `standings`                 | `drawn`                                            | `draws`                                                                 | renamed in seed **and** in `recompute/route.ts` |
| `competition_registrations` | player-KYC fields (`player_id`, `full_name`, dob…) | team table (`competition_id`, `team_id`, `status`)                      | register teams; tolerate trigger's 23505        |
| `invites`                   | `type`, `invited_role`, no token                   | `email/role/token`(NOT NULL UNIQUE)`/status/expires_at`                 | use `role`, generate `token`                    |
| `applications`              | `applicant_role`, `target_type`                    | `type`, `target_id`                                                     | seed fixed to real columns                      |

### C. Login redirect dead code (new, this session)

`app/(auth)/login` computed a role-based `dest` then always pushed `/league`. Referees and

### D. Standings recompute was silently broken in prod (new, this session)

recompute failed with PGRST204, so standings never updated. Fixed to `draws`.

## One remaining known issue (needs a schema decision — NOT shipped)

**Recruitment/applications feature reads phantom columns.** The applications API route
(`app/api/league/recruitment/applications/route.ts`) and several recruitment UI files read
`applicant_role` and `target_type`, which do **not** exist on the live `applications` table
(real columns: `type`, `target_id`). The feature is currently broken in prod (it
degrades — no crash on core flows). This is not a regression from this session; it predates
it. Two options, your call:

- **Migration (lower risk):** add `applicant_role` and `target_type` columns to
  `applications` to match what the code already expects, and backfill from `type`.
- **Refactor:** change the route + UI to use `type`/`target_id`.
  This is a good candidate for the multi-agent parallel workflow (one agent owns the
  migration + route, another owns the UI files).
